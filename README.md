# Игродром — площадка HTML5-игр

Каталог бесплатных браузерных игр: поиск, категории, подборки, страница игры с оценками.
Для авторов — кабинет: загрузка игр (ZIP-архив или один HTML), модерация, статистика запусков.
Без внешних зависимостей: Node.js 22.13+ (встроенные `http`, `node:sqlite`, `zlib`).

## Структура репозитория

| Путь | Что там |
|---|---|
| `server/` | сервер и API |
| `public/` | каталог (`index.html`), страница игры (`game.html`), `developers.html`, кабинет автора, `app.js` — общий код |
| `public/games/<slug>/` | демо-игры: `index.html`, `cover.svg`, `meta.json` |
| `scripts/build-catalog.js` | собирает `public/games/catalog.json` для статической версии |
| `test/` | тесты (`npm test`) |
| `Dockerfile`, `docker-compose.yml`, `Caddyfile` | деплой |
| `DESIGN.md` | дизайн-система: цвета, шрифты, раскладка, принципы — сверяйтесь при изменениях интерфейса |
| `.claude/skills/frontend-design/` | навык Anthropic для Claude Code: как не делать шаблонный «ИИ-дизайн» (Apache 2.0) |
| `public/fonts/` | шрифты Unbounded и Onest (кириллица и латиница), лицензия OFL |

## Локальный запуск

```bash
ADMIN_EMAILS=you@example.com npm start
```

Откройте http://localhost:3000. Кабинет автора: http://localhost:3000/cabinet.html.
Чтобы стать модератором, зарегистрируйтесь с email из `ADMIN_EMAILS`.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `PORT` | `3000` | Порт сервера |
| `DATA_DIR` | `./data` | База SQLite, файлы игр, секрет ссылок предпросмотра (в git не попадает) |
| `ADMIN_EMAILS` | пусто | Email модераторов через запятую |
| `COOKIE_SECURE` | выкл. | `1` — cookie только по HTTPS (в продакшене обязательно) |
| `TRUST_PROXY` | выкл. | `1` — брать IP посетителя из `X-Forwarded-For` (только за своим прокси) |
| `PREVIEW_SECRET` | создаётся в `DATA_DIR` | Ключ подписи ссылок предпросмотра |
| `STATS_TZ` | `Europe/Moscow` | Часовой пояс, по которому статистика делится на дни |
| `SEED_DEMO_GAMES` | вкл. | `0` — не заводить демо-игры из `public/games/` в базу |

Тесты: `npm test`. Проверка, что сервер жив: `GET /healthz`.

## Деплой

Нужен сервер с постоянным диском: в базе аккаунты, на диске файлы игр. Vercel, Netlify и GitHub Pages
**не подойдут** — там нет постоянного диска и долгоживущего процесса.

### Где размещать

Рекомендую VPS в России (Timeweb Cloud, Selectel, REG.RU, Beget и т. п.), Ubuntu 22.04/24.04,
1 vCPU и 1–2 ГБ памяти, ~200–500 ₽/мес — для старта хватит.

Почему именно в России: сайт хранит email пользователей, это персональные данные. По 152-ФЗ данные
граждан РФ нужно записывать и хранить в базах на территории России, а оператор персональных данных
подаёт уведомление в Роскомнадзор. Уточните детали у юриста до запуска.

### Шаги (≈15 минут)

1. Купите VPS и домен. В DNS домена создайте A-запись на IP сервера, подождите, пока она заработает
   (`ping ваш-домен` показывает IP сервера).
2. Зайдите на сервер и поставьте Docker:
   ```bash
   ssh root@IP_СЕРВЕРА
   curl -fsSL https://get.docker.com | sh
   ```
3. Скачайте проект. Если репозиторий приватный, нужен токен GitHub с доступом на чтение:
   ```bash
   git clone -b claude/yandex-games-alternative-uzcl2b https://github.com/TopSteam53/woodforma-demo.git igrodrom
   cd igrodrom
   ```
4. Настройте и запустите:
   ```bash
   cp .env.example .env
   nano .env            # DOMAIN=ваш-домен, ADMIN_EMAILS=ваш@email
   docker compose up -d --build
   ```
5. Откройте `https://ваш-домен` — сертификат Let's Encrypt Caddy выпустит сам за ~минуту.
   Зарегистрируйтесь с email из `ADMIN_EMAILS` — у вас появится раздел «Модерация».

Если `docker compose` не может скачать образы (лимиты или блокировки Docker Hub), добавьте зеркало
в `/etc/docker/daemon.json`: `{"registry-mirrors": ["https://mirror.gcr.io"]}`, затем `systemctl restart docker`.

### Обслуживание

```bash
# Обновить до свежей версии из git
git pull && docker compose up -d --build

# Логи
docker compose logs -f app

# Бэкап данных (пара секунд простоя, чтобы база была целостной)
docker compose stop app
docker compose run --rm --no-deps --entrypoint tar app czf - -C /data . > backup-$(date +%F).tar.gz
docker compose start app
```

Храните бэкапы не на том же сервере. Восстановление: остановить `app`, распаковать архив в том
`igrodrom-data`, запустить.

## Как устроено

- `server/app.js` — HTTP-сервер и API, `server/db.js` — схема SQLite, `server/auth.js` — пароли и сессии,
  `server/zip.js` — распаковка ZIP (встроенный `zlib`, без зависимостей).
- `public/` — витрина (`index.html`), кабинет автора (`cabinet.html`), демо-игры.
- Каждая игра лежит в своей папке `DATA_DIR/games/<id>/` (точка входа — `index.html`), метаданные — в `DATA_DIR/igrodrom.db`.
  Игры старого формата (`games/<id>.html`) при запуске сами переезжают в папки.

Путь игры: автор загружает → статус «на модерации» → модератор одобряет или отклоняет с причиной →
одобренная игра появляется в каталоге и открывается по `/play/<id>/`.

## Каталог

- **Главная** — поиск, категории (только те, где есть игры), подборки «Популярные» и «Новые», сетка всех игр
  с сортировкой. Поиск и категория попадают в адрес: `index.html?q=змейка`, `index.html?category=Аркады`.
- **Карточка** — обложка 16:9, возрастная метка, «Новинка» для игр младше 14 дней, доля положительных оценок
  (показывается от 3 оценок), категория.
- **Страница игры** `game.html?id=…` — обложка с кнопкой «Играть» (игра загружается по нажатию), «Во весь экран»,
  «Поделиться», 👍/👎, «Об игре», «Как играть», информация, похожие игры.
- **Оценки** — одна на игру от браузера (анонимный cookie `vid`), можно передумать или снять.
- **Демо-игры** из `public/games/<slug>/` при запуске сервера заводятся в базу как одобренные игры
  от имени «Игродрома» (выключается `SEED_DEMO_GAMES=0`). Обновили `meta.json` — описание обновится при перезапуске.
- **Без сервера** (GitHub Pages) каталог берётся из `games/catalog.json`; оценки, счётчики и кабинет недоступны,
  вверху висит плашка «Демо-версия». После изменения `meta.json` выполните `npm run build:catalog`
  (тест проверяет, что файл не устарел).

## SDK и сохранения

Игры работают в песочнице без `localStorage` и cookie, поэтому сохраняют прогресс через SDK.

- `public/sdk/v1.js` — подключается игрой: `Igrodrom.init()` → `sdk.data.get() / set(value) / clear()`.
  Значение — любой JSON до 64 КБ; частые `set` склеиваются (не чаще 1 записи в секунду, последняя побеждает).
- `public/sdk-host.js` — сторона страницы игры (`game.html`). Принимает сообщения только от своего iframe,
  id игры берёт со страницы — игра не может прочитать чужое сохранение.
- Хранение: на сервере — таблица `game_saves`, за игроком по cookie `vid`; без сервера (GitHub Pages) —
  в `localStorage` страницы. Вне площадки SDK сам сохраняет в `localStorage` игры или в память.
- API: `GET/PUT/DELETE /api/games/:id/save`, не больше 60 записей в минуту на игрока и игру.
- Документация для авторов — раздел «Сохранения» на `developers.html`.

## Статистика

- **Запуск** — игрок открыл одобренную игру в каталоге. Повторное открытие тем же игроком в течение
  30 минут — та же сессия, не новый запуск. Заходы напрямую по `/play/<id>/` не считаются.
- **Игроки** — уникальные за день, по анонимному cookie `vid` (в базе только его хэш); в отчёте — сумма по дням.
- **Время в игре** — браузер присылает при закрытии игры. Считается только время, пока вкладка видна;
  не больше реально прошедшего с открытия и не больше 2 часов на сессию, один раз на открытие.
- **Защита от накрутки (базовая):** боты по User-Agent не считаются; с одного IP — не больше 30 запусков
  одной игры в день; неодобренные игры не считаются.
- Хранение: агрегаты по дням в `play_daily`; список «кто играл сегодня» в `play_visitors` — старше 2 дней удаляется.

В кабинете автора: итоги за 7/30/90 дней, график запусков по дням (с таблицей для тех, кому удобнее цифры)
и таблица по играм. В каталоге на карточке видно общее число запусков.

## Требования к загружаемой игре

| | Лимит |
|---|---|
| ZIP-архив | до 20 МБ, до 1000 файлов, распакованный — до 50 МБ |
| Один HTML-файл | до 5 МБ |
| Точка входа | `index.html` в корне архива или в единственной папке внутри него |
| Пути к ресурсам | относительные: `img/hero.png`, а не `/img/hero.png` |
| Обложка (необязательно) | `cover.png`, `cover.jpg`, `cover.webp` или `cover.svg` в корне архива, 16:9 |
| Иконка (необязательно) | `icon.png`, `icon.webp` или `icon.svg` в корне архива, квадрат 1:1, без мелкого текста — видна размером 48–128 px |

Не принимаются: архивы с паролем, ZIP64, симлинки, пути с `..` или абсолютные, дубли имён.
Мусор macOS (`__MACOSX/`, `.DS_Store`) и `Thumbs.db` пропускается. Русские имена файлов из архивов
Windows (кодировка CP866) читаются корректно.

## API

| Метод | Путь | Кто | Что |
|---|---|---|---|
| POST | `/api/register` | все | `{email, password, name}` → аккаунт + вход |
| POST | `/api/login` / `/api/logout` | все | вход / выход |
| GET | `/api/me` | все | текущий пользователь или `null` |
| GET | `/api/games` | все | одобренные игры (с обложкой, возрастом, оценками, запусками) |
| GET | `/api/games/:id` | все | карточка игры: описание, правила, своя оценка `my_vote` |
| PATCH | `/api/games/:id` | автор игры | `{title, genre, age, description, how_to_play}` |
| POST | `/api/games/:id/vote` | все | `{value: 1 \| -1 \| 0}` |
| GET / PUT / DELETE | `/api/games/:id/save` | все | сохранение игры для этого игрока; PUT `{data}` до 64 КБ |
| GET | `/api/categories` | все | категории и возрастные метки |
| POST | `/api/games?title=&genre=` | автор | тело запроса — ZIP-архив или HTML-файл |
| GET | `/api/my/games` | автор | свои игры со статусами и `preview_url` |
| DELETE | `/api/games/:id` | автор игры | удалить |
| GET | `/api/admin/games?status=pending` | модератор | очередь с `preview_url` |
| POST | `/api/admin/games/:id` | модератор | `{action: "approve" \| "reject", reason}` |
| POST | `/api/games/:id/play` | все | засчитать запуск (`{counted}`) |
| POST | `/api/games/:id/play-end` | все | `{seconds}` — время сессии |
| GET | `/api/my/stats?days=30` | автор | итоги, по дням, по играм, оценка дохода (1–365 дней) |
| GET | `/play/:id/<файл>` | все | файлы одобренной игры |
| GET | `/preview/:id.:exp.:sig/<файл>` | у кого есть ссылка | любая игра; подписанная ссылка живёт 6 часов |

## Безопасность

- Пароли хэшируются scrypt с солью. Сессия — случайный токен в cookie `HttpOnly; SameSite=Lax`, в базе хранится только его хэш.
- После 10 неудачных входов за 15 минут вход для этой пары IP+email блокируется.
- Запись с чужих сайтов отклоняется по заголовку `Origin`.
- Игры отдаются с `Content-Security-Policy: sandbox allow-scripts`: чужой код получает «пустой» origin
  и не видит cookie, хранилище и API площадки. Дополнительно iframe на витрине тоже в `sandbox`.
- Неодобренные игры открываются только по ссылке с HMAC-подписью: проверить cookie нельзя, потому что
  у ресурсов, которые грузит игра из песочницы, cookie нет. Подпись привязана к id игры и сроку.
- ZIP проверяется до записи на диск: выход за папку (`../`), симлинки, zip-бомбы (размер после распаковки
  ограничен заявленным в заголовке, сумма — 50 МБ), CRC каждого файла. Файлы пишутся во временную папку
  и переносятся целиком, при ошибке она удаляется.

## Что ещё не сделано

- Сборки Unity WebGL со сжатыми файлами `.gz`/`.br`: им нужен заголовок `Content-Encoding`, сейчас его нет.
  Пока такие игры надо собирать без сжатия (Compression Format: Disabled).
- Распаковка синхронная: архив на 50 МБ на долю секунды блокирует сервер. При большом потоке загрузок
  стоит вынести её в отдельный поток (`worker_threads`).
- Подтверждение email и сброс пароля.
- Отзывы игроков; аккаунты игроков — чтобы сохранения переезжали между устройствами; в SDK: таблицы рекордов, достижения, пауза при сворачивании вкладки.
- Подключение рекламной сети и выплаты.
- Серьёзный антифрод до первых выплат: время и запуски присылает браузер, их можно подделать.
  Нужны проверки по поведению, по IP-подсетям, сверка с показами из рекламной сети.
- Политика конфиденциальности с описанием cookie `sid` и `vid`.
- Отдельный домен для игр (например, `play.igrodrom.ru`) — ещё один слой изоляции чужого кода.
- Автоматические бэкапы по расписанию и мониторинг доступности.
- Ограничитель попыток входа живёт в памяти одного процесса: для нескольких копий сервера нужен общий (Redis).
