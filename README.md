# Gamely — площадка HTML5-игр

Каталог бесплатных браузерных игр: поиск, категории, подборки, страница игры с оценками.
Игроки входят, чтобы прогресс был доступен на всех устройствах. Разработчики подают заявку, после одобрения
загружают игры (ZIP-архив или один HTML); каждая игра проходит модерацию. Есть статистика запусков.
Без внешних зависимостей: Node.js 22.13+ (встроенные `http`, `node:sqlite`, `zlib`).

## Структура репозитория

| Путь | Что там |
|---|---|
| `server/` | сервер и API |
| `public/` | каталог (`index.html`), страница игры (`game.html`), `developers.html`, вход (`login.html`), профиль (`account.html`), кабинет разработчика (`cabinet.html`), `app.js` — общий код |
| `public/games/<slug>/` | демо-игры: `index.html`, обложка `cover.*`, иконка `icon.*`, `meta.json` |
| `scripts/build-catalog.js` | собирает `public/games/catalog.json` для статической версии |
| `test/` | тесты (`npm test`) |
| `Dockerfile`, `docker-compose.yml`, `Caddyfile` | деплой |
| `DESIGN.md` | дизайн-система: цвета, шрифты, раскладка, принципы — сверяйтесь при изменениях интерфейса |
| `.claude/skills/frontend-design/` | навык Anthropic для Claude Code: как не делать шаблонный «ИИ-дизайн» (Apache 2.0) |
| `public/fonts/` | шрифты Unbounded и Onest (кириллица и латиница), лицензия OFL |

## Локальный запуск

```bash
ADMIN_EMAILS=you@example.com npm start
```

Откройте http://localhost:3000. Кабинет разработчика: http://localhost:3000/cabinet.html.
Чтобы стать владельцем площадки, зарегистрируйтесь с email из `ADMIN_EMAILS`.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `PORT` | `3000` | Порт сервера |
| `DATA_DIR` | `./data` | База SQLite, файлы игр, секрет ссылок предпросмотра (в git не попадает) |
| `ADMIN_EMAILS` | пусто | Email владельцев площадки через запятую (модераторов они назначают в кабинете) |
| `COOKIE_SECURE` | выкл. | `1` — cookie только по HTTPS (в продакшене обязательно) |
| `TRUST_PROXY` | выкл. | `1` — брать IP посетителя из `X-Forwarded-For` (только за своим прокси) |
| `PREVIEW_SECRET` | создаётся в `DATA_DIR` | Ключ подписи ссылок предпросмотра |
| `STATS_TZ` | `Europe/Moscow` | Часовой пояс, по которому статистика делится на дни |
| `SEED_DEMO_GAMES` | вкл. | `0` — не заводить демо-игры из `public/games/` в базу |

Тесты: `npm test`. Проверка, что сервер жив: `GET /healthz`.

## Деплой

Нужен сервер с постоянным диском: в базе аккаунты, на диске файлы игр. Vercel, Netlify и GitHub Pages
**не подойдут** — там нет постоянного диска и долгоживущего процесса.

### Где размещать

Рекомендую VPS в России (Timeweb Cloud, Selectel, REG.RU, Beget и т. п.), Ubuntu 22.04/24.04,
1 vCPU и 1–2 ГБ памяти, ~200–500 ₽/мес — для старта хватит.

Почему именно в России: сайт хранит email пользователей, это персональные данные. По 152-ФЗ данные
граждан РФ нужно записывать и хранить в базах на территории России, а оператор персональных данных
подаёт уведомление в Роскомнадзор. Уточните детали у юриста до запуска.

### Одной командой

На свежем Ubuntu 22.04/24.04 (зайдя по SSH под root):

```bash
curl -fsSL https://raw.githubusercontent.com/TopSteam53/igrodrom/main/scripts/server-setup.sh -o server-setup.sh
sh server-setup.sh 1-2-3-4.sslip.io you@example.com
```

Скрипт ставит Docker (с зеркалом образов), включает файрвол, разворачивает сайт с HTTPS и ежедневный бэкап базы
(`scripts/backup.sh`, 04:30, 14 дней в `/var/backups/igrodrom`). Без своего домена берите адрес по IP вида
`1-2-3-4.sslip.io`. Повторный запуск обновляет сайт до свежей версии и не трогает `.env`.

### Шаги вручную (≈15 минут)

1. Купите VPS и домен. В DNS домена создайте A-запись на IP сервера, подождите, пока она заработает
   (`ping ваш-домен` показывает IP сервера).
2. Зайдите на сервер и поставьте Docker:
   ```bash
   ssh root@IP_СЕРВЕРА
   curl -fsSL https://get.docker.com | sh
   ```
3. Скачайте проект. Если репозиторий приватный, нужен токен GitHub с доступом на чтение:
   ```bash
   git clone https://github.com/TopSteam53/igrodrom.git igrodrom
   cd igrodrom
   ```
4. Настройте и запустите:
   ```bash
   cp .env.example .env
   nano .env            # DOMAIN=ваш-домен, ADMIN_EMAILS=ваш@email
   docker compose up -d --build
   ```
5. Откройте `https://ваш-домен` — сертификат Let's Encrypt Caddy выпустит сам за ~минуту.
   Зарегистрируйтесь с email из `ADMIN_EMAILS` — у вас появится раздел «Модерация» с вкладкой «Команда».

Если `docker compose` не может скачать образы (лимиты или блокировки Docker Hub), добавьте зеркало
в `/etc/docker/daemon.json`: `{"registry-mirrors": ["https://mirror.gcr.io"]}`, затем `systemctl restart docker`.

### Обслуживание

```bash
# Обновить до свежей версии из git
git pull && docker compose up -d --build

# Логи
docker compose logs -f app

# Бэкап данных (пара секунд простоя, чтобы база была целостной)
docker compose stop app
docker compose run --rm --no-deps --entrypoint tar app czf - -C /data . > backup-$(date +%F).tar.gz
docker compose start app
```

Храните бэкапы не на том же сервере. Восстановление: остановить `app`, распаковать архив в том
`igrodrom-data`, запустить.

## Как устроено

- `server/app.js` — HTTP-сервер и API, `server/db.js` — схема SQLite, `server/auth.js` — пароли и сессии,
  `server/zip.js` — распаковка ZIP (встроенный `zlib`, без зависимостей).
- `public/` — витрина (`index.html`), кабинет разработчика (`cabinet.html`), демо-игры.
- Каждая игра лежит в своей папке `DATA_DIR/games/<id>/` (точка входа — `index.html`), метаданные — в `DATA_DIR/igrodrom.db`.
  Игры старого формата (`games/<id>.html`) при запуске сами переезжают в папки.

Путь игры: автор загружает → статус «на модерации» → модератор одобряет или отклоняет с причиной →
одобренная игра появляется в каталоге и открывается по `/play/<id>/`.

## Игроки и разработчики

- **Игрок** — любой, кто зарегистрировался (`login.html`). Вход нужен не для игры, а чтобы прогресс жил в аккаунте:
  сохранения вошедшего игрока хранятся за аккаунтом и доступны с любого устройства. При входе прогресс,
  накопленный гостем в этом браузере, переезжает в аккаунт (если у аккаунта уже есть сохранение игры —
  остаётся более свежее). Профиль `account.html`: «Продолжить играть» и статус заявки разработчика.
- **Разработчик** — игрок с одобренной заявкой. Заявка (имя или студия, о себе, ссылки, контакт) подаётся
  в `cabinet.html`; модератор одобряет или отклоняет её с причиной, после отказа заявку можно исправить и подать снова.
  Загружать и редактировать игры, смотреть статистику можно только с одобренной заявкой. Каждая игра
  по-прежнему проходит модерацию.
- **Модератор** — назначает владелец в кабинете: «Модерация» → «Команда», по почте зарегистрированного аккаунта.
  Проверяет заявки разработчиков и игры (публикует, отклоняет, снимает с публикации — всегда с причиной).
  Не может проверять свою заявку и свои игры, удалять чужие игры и менять команду. Снятие действует сразу.
- **Владелец** — email из `ADMIN_EMAILS`: всё, что модератор, плюс команда, удаление любых игр и публикация без заявки.
- **Журнал** — каждое решение модератора и изменение команды пишется в `moderation_log`: кто, что, когда, причина.
- Авторы, у которых игры появились до введения заявок, при запуске сервера автоматически становятся
  одобренными разработчиками.

## Каталог

- **Главная** — поиск, категории (только те, где есть игры), подборки «Популярные» и «Новые», сетка всех игр
  с сортировкой. Поиск и категория попадают в адрес: `index.html?q=змейка`, `index.html?category=Аркады`.
- **Карточка** — обложка 16:9, возрастная метка, «Новинка» для игр младше 14 дней, доля положительных оценок
  (показывается от 3 оценок), категория.
- **Страница игры** `game.html?id=…` — обложка с кнопкой «Играть» (игра загружается по нажатию), «Во весь экран»,
  «Поделиться», 👍/👎, «Об игре», «Как играть», информация, похожие игры.
- **Оценки** — одна на игру от браузера (анонимный cookie `vid`), можно передумать или снять.
- **Демо-игры** из `public/games/<slug>/` при запуске сервера заводятся в базу как одобренные игры
  от имени «Gamely» (выключается `SEED_DEMO_GAMES=0`). Обновили `meta.json` — описание обновится при перезапуске.
  `"featured": 1` в `meta.json` ставит игру первой в подборку на главной.
  «Мурмерж» (`public/games/murmerzh`) — игра с Яндекс Игр, перенесённая без изменений кода: заменён только путь
  к SDK (`/sdk.js` → `../../sdk.js`, чтобы работало и на GitHub Pages) и добавлены обложка и иконка.
- **Без сервера** (GitHub Pages) каталог берётся из `games/catalog.json`; оценки, счётчики и кабинет недоступны,
  вверху висит плашка «Демо-версия». После изменения `meta.json` выполните `npm run build:catalog`
  (тест проверяет, что файл не устарел).

## SDK и сохранения

Игры работают в песочнице без `localStorage` и cookie, поэтому сохраняют прогресс через SDK.

- `public/sdk/v1.js` — подключается игрой: `Gamely.init()` → `sdk.data.get() / set(value) / clear()`,
  `sdk.player`, `sdk.game.ready/start/stop()`, `sdk.ads.fullscreen() / rewarded()`, `sdk.leaderboard.*`,
  `sdk.coins.balance() / spend(amount, title)`, `sdk.feedback.canReview() / request()`.
  Значение — любой JSON до 200 КБ; частые `set` склеиваются (не чаще 1 записи в секунду, последняя побеждает).
  Рекламной сети пока нет: полноэкранная реклама не показывается, награда за просмотр выдаётся сразу.
- `public/sdk/yandex.js` — совместимость с Яндекс Игры SDK v2 (`YaGames.init()` и объект `ysdk`) поверх v1:
  облачные сохранения, статистика, `getStorage`, `localStorage` в песочнице, реклама, `LoadingAPI`, лидерборды
  (таблицы рекордов площадки), отзывы; покупки, бонусы и мультиплеер — заглушки. `public/sdk.js` — v1 и yandex.js одним файлом
  (`npm run build:sdk`, тест проверяет, что он не устарел). При загрузке игры сервер меняет ссылки на
  `https://yandex.ru/games/sdk/v2` на `/sdk.js`, поэтому игру с Яндекса загружают тем же архивом.
  Проверено на настоящей сборке с Яндекс Игр: запускается без правок.
- `public/sdk-host.js` — сторона страницы игры (`game.html`). Принимает сообщения только от своего iframe,
  id игры берёт со страницы — игра не может прочитать чужое сохранение.
- Хранение: на сервере — таблица `game_saves`, за игроком по cookie `vid`; без сервера (GitHub Pages) —
  в `localStorage` страницы. Вне площадки SDK сам сохраняет в `localStorage` игры или в память.
- API: `GET/PUT/DELETE /api/games/:id/save`, не больше 60 записей в минуту на игрока и игру.
- Документация для авторов — раздел «Сохранения» на `developers.html`.

## Почта, рекорды, монетки, отзывы

- **Почта.** При регистрации уходит письмо со ссылкой подтверждения (`verify.html`, живёт 3 дня). «Забыли пароль?»
  на странице входа ведёт на `reset.html`: ссылка живёт час, после смены пароля закрываются все сессии.
  Ответ на запрос сброса одинаковый для любой почты — по нему нельзя узнать, кто зарегистрирован.
  Настройки: `SMTP_URL`, `MAIL_FROM`, `SITE_URL` (`.env.example`), SMTP-клиент свой (`server/mail.js`).
  Без `SMTP_URL` письма печатаются в лог сервера, а подтверждение почты не требуется. С почтой без подтверждения
  нельзя подать заявку разработчика и писать отзывы.
- **Таблицы рекордов** (`leaderboard_scores`). Пишут только вошедшие игроки, хранится лучший результат, больше — лучше.
  На странице игры — блок «Рекорды» (самая заполненная таблица, переключатель, если таблиц несколько).
- **Монетки** — валюта сайта (`server/economy.js`, баланс в `users.coins`, каждое движение — в `coin_ledger`).
  Откуда: 50 в подарок при регистрации, бонус за вход раз в день (забирается сам при заходе на любую страницу),
  награды (ниже), выдача владельцем из админки, покупка через ЮKassa. За время в игре больше не начисляются (`coins/tick` отвечает нулём).
  Игра тратит монетки через SDK, подтверждает игрок в окне страницы (вне песочницы). Баланс — в шапке, история — в профиле.
- **Награды игрокам** (`server/rewards.js`, только монетками; выдаются один раз — отметка и начисление в одной транзакции):
  - *Серия входов*: дни 1–7 дают 5, 6, 7, 8, 10, 12, 20, потом круг сначала, а счётчик дней подряд растёт
    (`users.daily_streak`). Пропуск календарного дня (по `STATS_TZ`) — серия с первого дня. Журнал — `daily`.
  - *Достижения* (`player_achievements`, журнал — `achievement`): 13 штук по данным сайта — рекорды, отзывы, серия,
    покупка в игре, друзья, призовые места в турнире, подтверждённая почта, аватарка. Проверяются при открытии профиля,
    после бонуса за вход, рекорда и подтверждения почты.
  - *Турнир недели* (`tournaments`, `tournament_scores`): владелец в админке выбирает игру и её таблицу рекордов на текущую
    или следующую неделю (понедельник 00:00 — воскресенье 23:59 по `STATS_TZ`). Каждый результат в эту таблицу за неделю идёт
    и в зачёт турнира (лучший). Призы 150/100/50 трём лучшим выдаёт первый запрос после конца недели — крона нет.
    Блок на главной и страница `/tournament`; без турнира их не видно.
  - *Пригласи друга*: у игрока постоянная ссылка `/?invite=<код>` (случайный код в `users.invite_code`), страница запоминает
    код в cookie `invite` на 30 дней. Когда друг зарегистрировался и подтвердил почту, пригласившему 30 монеток, другу 20
    (журнал — `referral`, таблица `invites`), не больше 20 друзей на игрока. Себя пригласить нельзя: тот же браузер (`vid`),
    тот же адрес, что при регистрации пригласившего (хранится HMAC адреса, не сам адрес), или вход пригласившего в этом браузере.
- **Покупка монеток (ЮKassa).** Пакеты — `COIN_PACKS` («монетки:рубли»), ключи — `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`
  (ключ `test_…` — тестовый магазин: карта 5555 5555 5555 4477). Игрок выбирает пакет → заказ `coin_orders` → оплата на
  странице ЮKassa → возврат в профиль. Монетки зачисляются один раз, только после того как сервер сам запросил платёж
  у ЮKassa и сверил статус, сумму и номер заказа: уведомления ЮKassa не подписаны, им не верим на слово.
  В личном кабинете ЮKassa укажите HTTP-уведомления на `https://<сайт>/api/payments/yookassa` (события
  `payment.succeeded`, `payment.canceled`). Чек по 54-ФЗ: `YOOKASSA_RECEIPT=1` (ИП/ООО с «Чеками от ЮKassa»),
  самозанятым не нужен — ЮKassa сама передаёт продажу в «Мой налог».
- **Аватарки** (`server/avatars.js`). 16 готовых зверей в плоском стиле (`public/avatars/*.svg`, генератор — `scripts/avatars-svg.mjs`)
  или своя картинка: браузер обрезает её до квадрата 256×256 и стирает метаданные фото, сервер проверяет формат
  по сигнатуре. Своя видна другим после проверки модератором; модераторам ставится сразу.
- **Админка** (`admin.html`, `server/admin.js`): обзор с графиком регистраций и очередями, пользователи (поиск по имени,
  почте и номеру, фильтры, карточка с историей монеток), блокировка (вход закрыт, сессии сброшены), модерация игр,
  обновлений, заявок и аватарок, журнал. Только владельцу: выручка и платежи, выдача монеток, команда, удаление игр.
- **Отзывы** (`game_reviews`). Один на игру от аккаунта, можно изменить и удалить; модератор удаляет чужие
  с записью в журнал (`review.delete`).

## Ассеты из Blender

«Звёздный патруль» (`public/games/starpatrol`) нарисован спрайтами, отрендеренными в Blender: корабль, враги,
астероиды, кристалл, планета, бесшовный фон-туманность, обложка и иконка. Всё строится скриптом из примитивов
и шейдерных узлов — исходник `scripts/blender/starpatrol.py`, файлов .blend нет. Пересобрать (Blender 4.2+):

```bash
blender --background --factory-startup --python scripts/blender/starpatrol.py -- public/games/starpatrol
```

Можно перерендерить отдельные ассеты: `… -- public/games/starpatrol ship cover`.

## Поисковики и превью ссылок

- `/robots.txt` закрывает от индексации API, превью и служебные страницы (вход, профиль, кабинет).
  `/sitemap.xml` собирается из каталога: главная, страницы всех одобренных игр, правила и контакты.
- В каждую страницу сервер вставляет `og:*`-теги и `canonical`. Telegram, ВК и поисковики не выполняют скрипты,
  поэтому страница игры отдаётся сразу с её названием, описанием и картинкой.
- Картинка превью игры — `og.jpg` (или `og.png`) в папке игры, иначе обложка, если она растровая, иначе общая
  `public/og.jpg`. SVG мессенджеры не показывают, поэтому для демо-игр картинки отрендерены заранее
  (Windows, нужен Chrome или Edge): `powershell -ExecutionPolicy Bypass -File scripts/og-images.ps1 [игра …]`.
  Без аргументов скрипт пересобирает картинки всех игр и коллаж для главной.
- Несуществующие адреса получают страницу `public/404.html` со статусом 404. API по-прежнему отвечает JSON.

## Реклама

Игры просят рекламу через SDK (`sdk.ads.fullscreen()/rewarded()` или `ysdk.adv.*`), показывает её страница игры
(`public/ads.js`). Сеть подключается один раз для всех игр, настройками в `.env` — см. `.env.example`.

- `ADS_PROVIDER` — сеть для полноэкранной рекламы и рекламы за награду: `none` (по умолчанию), `test`, `yandex`, `vk`, `google`;
  `ADS_BANNER` — сеть для баннера под игрой (по умолчанию та же).
- `test` — тестовая реклама на 5 секунд: проверить весь путь до одобрения сети.
- Частота: полноэкранная не чаще раза в `ADS_FULLSCREEN_INTERVAL` (60) секунд и не в первые `ADS_FIRST_DELAY` (30) секунд игры.
  За награду — только по нажатию игрока; если сеть не умеет такой формат или её нет, награда выдаётся сразу,
  если реклама есть, но не догрузилась или её закрыли раньше — награды нет.
- На время показа игра получает `pause`/`resume` (в Яндекс-играх — `game_api_pause`/`game_api_resume`, `onOpen` — когда реклама реально открылась).
- Показы считаются по играм и дням (`ad_daily`, `POST /api/games/:id/ad`) и видны авторам в кабинете.
- `/ads.txt` — из файла `DATA_DIR/ads.txt` или переменной `ADS_TXT`.
- Код вызова РСЯ сделан по документации (`Ya.Context.AdvManager.render`, `type: 'fullscreen' | 'rewarded'`, `onRewarded`);
  при подключении сверьте его с кодом блока в кабинете partner.yandex.ru. Реклама за награду в РСЯ включается через поддержку.

Страницы, которые сети проверяют при модерации: `contacts.html`, `terms.html`, `privacy.html`. Реквизиты берутся
из `SITE_EMAIL`, `SITE_TELEGRAM`, `SITE_OWNER`; счётчик Яндекс Метрики — `METRIKA_ID`. Тексты правил и политики —
шаблон: перед запуском проверьте их под свой статус (самозанятый, ИП).

## Статистика

- **Запуск** — игрок открыл одобренную игру в каталоге. Повторное открытие тем же игроком в течение
  30 минут — та же сессия, не новый запуск. Заходы напрямую по `/play/<id>/` не считаются.
- **Игроки** — уникальные за день, по анонимному cookie `vid` (в базе только его хэш); в отчёте — сумма по дням.
- **Время в игре** — браузер присылает при закрытии игры. Считается только время, пока вкладка видна;
  не больше реально прошедшего с открытия и не больше 2 часов на сессию, один раз на открытие.
- **Защита от накрутки (базовая):** боты по User-Agent не считаются; с одного IP — не больше 30 запусков
  одной игры в день; неодобренные игры не считаются.
- Хранение: агрегаты по дням в `play_daily`; список «кто играл сегодня» в `play_visitors` — старше 2 дней удаляется.

В кабинете автора: итоги за 7/30/90 дней, график запусков по дням (с таблицей для тех, кому удобнее цифры)
и таблица по играм. В каталоге на карточке видно общее число запусков.

## Требования к загружаемой игре

| | Лимит |
|---|---|
| ZIP-архив | до 100 МБ, до 5000 файлов, распакованный — до 300 МБ (как у Яндекс Игр) |
| Один HTML-файл | до 5 МБ |
| Точка входа | `index.html` в корне архива или в единственной папке внутри него |
| Пути к ресурсам | относительные: `img/hero.png`, а не `/img/hero.png` |
| Обложка (необязательно) | `cover.png`, `cover.jpg`, `cover.webp` или `cover.svg` в корне архива, 16:9 |
| Иконка (необязательно) | `icon.png`, `icon.webp` или `icon.svg` в корне архива, квадрат 1:1, без мелкого текста — видна размером 48–128 px |

Не принимаются: архивы с паролем, ZIP64, симлинки, пути с `..` или абсолютные, дубли имён.
Мусор macOS (`__MACOSX/`, `.DS_Store`) и `Thumbs.db` пропускается. Русские имена файлов из архивов
Windows (кодировка CP866) читаются корректно.

## Безопасность

- Пароли хэшируются scrypt с солью. Сессия — случайный токен в cookie `HttpOnly; SameSite=Lax`, в базе хранится только его хэш.
- После 10 неудачных входов за 15 минут вход для этой пары IP+email блокируется.
- Регистрация защищена от ботов без сторонней капчи: форма получает подписанный билет и отправляется не раньше
  чем через 3 секунды (живой человек этого не замечает); скрытое поле-ловушка; не больше 10 аккаунтов в час
  и 30 в сутки с одного IP; ссылки и адреса в имени запрещены. Включается в `server/index.js` (`registerGuard`),
  в тестах выключено.
- Запись с чужих сайтов отклоняется по заголовку `Origin`.
- Игры отдаются с `Content-Security-Policy: sandbox allow-scripts`: чужой код получает «пустой» origin
  и не видит cookie, хранилище и API площадки. Дополнительно iframe на витрине тоже в `sandbox`.
- Неодобренные игры открываются только по ссылке с HMAC-подписью: проверить cookie нельзя, потому что
  у ресурсов, которые грузит игра из песочницы, cookie нет. Подпись привязана к id игры и сроку.
- ZIP проверяется до записи на диск: выход за папку (`../`), симлинки, zip-бомбы (размер после распаковки
  ограничен заявленным в заголовке, сумма — 300 МБ), CRC каждого файла. Файлы пишутся во временную папку
  и переносятся целиком, при ошибке она удаляется.

## Что ещё не сделано

- Игры, которые читают `localStorage` до `YaGames.init()`, при первом чтении могут получить пустое значение:
  сохранение приходит от площадки асинхронно. Полное решение — отдавать игры с отдельного домена
  (как `app-<id>.games.s3.yandex.net` у Яндекса) с `allow-same-origin`, тогда у игры будет настоящее хранилище.
- Распаковка синхронная: архив на 100 МБ на долю секунды блокирует сервер. При большом потоке загрузок
  стоит вынести её в отдельный поток (`worker_threads`).
- В SDK: достижения; таблицы рекордов с порядком «меньше — лучше» (для времени).
- Выплаты авторам по показам рекламы.
- Серьёзный антифрод до первых выплат: время и запуски присылает браузер, их можно подделать.
  Нужны проверки по поведению, по IP-подсетям, сверка с показами из рекламной сети.
- Отдельный домен для игр (например, `play.igrodrom.ru`) — ещё один слой изоляции чужого кода.
- Мониторинг доступности и копии бэкапов вне сервера.
- Ограничители попыток входа и регистраций живут в памяти одного процесса: для нескольких копий сервера нужен общий (Redis).
- Если бот научится ждать и менять IP, понадобится настоящая капча (например, Yandex SmartCaptcha).
